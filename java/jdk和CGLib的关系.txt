public interface IUserService {
    void query();
}

public class UserService implements IUserService {
    @Override
    public void query() {
        System.out.println("query");
    }
}

JDK：通过Proxy.newProxyInstance(...)，最终得到的代理对象，本质上类似：
class UserServiceProxy implements IUserService {
    private UserService target;

    public void query() {
        // AOP逻辑
        target.query();
    }
}

CGLIB
CGLIB 可以理解成生成：
class UserServiceProxy extends UserService {
    @Override
    public void query() {
        // AOP逻辑
        super.query();
    }
}

所以两者的核心差异就是：
JDK：
代理对象 implements 接口
CGLIB：
代理对象 extends 目标类

IOC、AOP、依赖倒置
IoC：控制权交给容器（以前是业务自己造对象：谁创建、谁组装、何时销毁，全是业务说了算。现在只跟容器打交道）
依赖注入（DI） :依赖是被「注入」进来的，不是自己找的。 这就是 DI，也是 IoC 最常见的落地方式。
依赖倒置（DIP） 是设计原则：都依赖抽象接口，不依赖具体实现。
AOP：不改业务类，也能在方法前后加逻辑。
