ReAct:思考（Reason）→ 行动（Act，调工具）→ 观察结果（Observe）→ 再思考 → … => 直到能给用户最终答案
3.规则识别 + LLM意图识别（诊断 / 配置 / 部署 / 监控等），高置信度走规则识别（毫秒级），不足再下沉 LLM，并带 LRU 缓存与失败重分类，减少误判和重复推理。
规则识别：不调用模型，只做关键词、正则表达式和上下文匹配。规则层会对每个意图打分。
例如用户输入：nginx 502了，帮我看看为什么挂了
规则同时命中了：502、挂了、“为什么……挂了”正则
规则可能得到：intent = DIAGNOSE、confidence = 0.8、entities = {service: nginx}。因为置信度达到 0.8，系统直接使用该结果。整个过程只是内存中的字符串匹配，通常不到 1ms，不需要网络请求，也不消耗模型 token。
“不足再下沉 LLM”：有些用户表达比较模糊，例如：服务器感觉有点慢，帮我瞧瞧。规则可能没有命中足够多的明确关键词，得到：
DIAGNOSE: 0.5
MONITOR:  0.3
最高分只有 0.5，不足 0.8。此时系统把消息交给第二层 LLMIntentClassifier。
“下沉”就是：第一层无法可靠判断，继续交给下一层处理。
LLM 会收到类似这样的 Prompt：
你是 SSH 运维意图识别系统。
可选意图：
DIAGNOSE、CONFIGURE、DEPLOY、MONITOR……
用户输入：
服务器感觉有点慢，帮我瞧瞧
仅返回 JSON。
模型可能返回：
{
  "intent": "DIAGNOSE",
  "confidence": 0.75,
  "entities": {},
  "candidates": ["MONITOR"]
}
因为 LLM 置信度达到 0.5，所以最终采用 LLM 的 DIAGNOSE。

LRU 是 Least Recently Used，意思是“最近最少使用淘汰”。缓存超过 200 条时，最久没有访问的结果先被删除。


4.用Provider/Reducer管道动态组装Prompt（采集终端环境、任务目标、里程碑、工具摘要、长期记忆）并按 token 预算裁剪历史，缓解长对话上下文膨胀。
Provider:用户说「帮我看 502」时，模型不能只看到这句话。Provider 会补上：你在 /var/log/nginx、最初任务是排查 502、上次 cat 报过权限错误、刚 tail 过 error.log。这些现场情报合在一起，才叫这一轮的上下文。
（采集终端环境、任务目标、里程碑、工具摘要、长期记忆）就是Provider采集的内容，用户原话可能只有一句「帮我看下 502」。模型真正看到的，还会在后面拼上这些：
[系统环境]     ← 终端环境：这台远程机此刻的操作系统、当前用户、工作目录。
[当前任务]     ← 任务目标： 这次对话一开始要干的事，不是最新一句闲聊。
[关键事件]     ← 里程碑： 对话里的转折点，不是每一句。正则扫出来的关键事件，例如：用户说「不对 / 换个思路」=> TASK_CHANGE、用户说「不要 / 停 / 别」=> USER_CORRECTION
[工具执行摘要] ← 工具摘要: 本会话里已经跑过的工具结果的压缩版，不是完整日志
[长期记忆]     ← 长期记忆: 跨会话存下来的经验：用户偏好、这台机环境、以前排查结论等，不是本轮聊天记录。

YAML 驱动的多框架 Agent 运行时
融合 Google ADK（Runner/Session/Tool）、Spring AI（ChatModel/MCP）、LangChain4j。通过 YAML 声明模型、指令、MCP 工具、Skills、子智能体和工作流（loop/parallel/sequential），启动时由 ArmoryService 按策略树装配。同一入口同时覆盖编码助手与 SSH 运维，支持 OpenAI 兼容模型热切换；意图识别模型与主对话模型可独立配置。

自研 ReAct 引擎 + Supervisor 监督
节点链为 RootNode → TaskBreakdownNode → AiCallNode → ToolCallNode → LoopDecisionNode → UserFeedbackNode。外层 AgentLoopExecutor 做监督：30s 空闲探测、最长约 10 分钟空闲超时、Token 预算预警、死循环检测、客户端断开取消。遇 413 Payload Too Large 时触发上下文压缩（优先 AI 摘要，失败再按优先级裁剪）并最多重试 3 次。对话以 SSE + NDJSON 长连接流式下发思考、工具调用与执行结果。

本地开发与远程 SSH 双通道工具面
本地侧提供读写/搜索/创建/删除文件、执行 Shell、编译、单测、Lint；远程侧通过 JSch 管理 SSH 连接与终端会话，支持命令执行、文件树、读写搜索。聊天会话可绑定 terminalSessionId，实现「对话驱动远程运维」。另通过 CommandDispatcher 把部分指令经 SSE 下发到前端执行并回收结果，形成「服务端决策、客户端落地」的混合执行模型。

企业级安全与并发控制
PermissionGuard 五层递进：参数结构校验 → 40+ 危险命令/敏感文件正则（如 rm -rf /、磁盘格式化、Fork 炸弹、强推主分支）→ 模糊命令 AI 二次分类 → 未知工具拒绝兜底 → 同会话连续拒绝后断路器降级。删除、改配置等操作为 CONDITIONAL，经 PermissionResolve 接口等人机确认后再唤醒阻塞执行。ToolConcurrencyController 让只读工具最多 5 路并发，写/执行类工具串行，避免远程状态互相覆盖。

分级意图识别与复杂任务拆解
IntentService：规则分类（置信度 ≥ 0.8 直接命中，耗时 < 1ms）→ LLM 分类（100–500ms），缓存键用 SHA-256，LRU 容量 200，并维护会话上下文做指代消解。复杂请求（部署、重构、迁移、全流程等）由 TaskBreakdownService 拆成 2–10 个子任务（标题、描述、预期工具），按 session 复用，驱动后续 ReAct 逐步执行。

上下文压缩、记忆与可观测性
混合裁剪历史消息，默认 Token 预算约 8000；工具结果智能截断。会话、消息、里程碑入库；CoreMemoryService 维护规则/偏好/纠正类长期记忆（上限 50 条，冷记忆淘汰），注入 Prompt。子代理最多 3 轮、120s 超时，防止无限循环。配套 Docker Compose 拉起 MySQL、Redis 及应用，便于环境复现。

Supervisor(SSE 流式、413 压缩重试、Token预算、死循环检测)：
1. SSE 流式：对话不是等全部跑完再返回，而是一条最长 30 分钟 的 HTTP 长连接，内容类型是 NDJSON（一行一个 JSON 事件）。
2. 413 压缩重试: 413 是模型网关的 Payload Too Large：发给大模型的对话历史太长，请求被拒。Supervisor 抓到这类异常后：
「413 压缩重试」= 请求太大 → 砍上下文 → 再试，而不是直接报错结束。
3.Token 是模型和上下文的长度计量。项目里有两层预算：单次调用前裁剪:约 8000,整次 Agent 循环:默认 20 万
4. 死循环检测
Agent 是「思考 → 调工具 → 再思考」循环。模型可能反复执行同一条命令（例如一直 ls 同一目录），或一轮里狂调工具。
节点链内（真正会停）：
每轮把「调用了哪些工具」做成签名。连续 2 轮 签名完全相同（diminishingReturnsThreshold = 2），判定收益递减，终止循环。另外还有最大轮数（配置里 chat≈10、agent≈20，流式入口里曾放到 50）、每轮最多约 5 次工具、全局最多约 200 次工具。
Supervisor 外层（主要是警告）：
跑完后算 总工具次数 / 总步数。如果密度高于 每轮最大工具数 × 2，认为「转得太疯」，给前端发 warning，不一定立刻杀掉。
另外空闲超过默认 10 分钟（每 30 秒检查一次）也会被 Supervisor 标成 idle_timeout 并取消，避免线程一直挂着。

1.五层权限守卫:
参数解析：从 JSON 里抽出 command/path
正则规则：rm -rf /、格式化磁盘等直接拒绝；rm、docker rm、git push 等要确认
AI 分类：规则没覆盖的模糊命令，再让模型判 ALLOW / CONFIRM / DENY
兜底：注释写「未知就拒绝」，实现里 AI 失败时往往放行，避免误杀
断路器：同一会话连续拒绝约 5 次，60 秒内禁止再调工具
2.人机确认:
不是所有命令都自动跑。命中 CONFIRM 时：
SSE 推 permission_confirm 给前端弹窗
ToolCallNode 阻塞最多约 30 秒
用户点允许/拒绝 → POST /api/v1/permission/resolve
同意才执行，还可改参数再跑；拒绝或超时则取消
3.读写并发隔离
只读（读文件、列表、搜索）：最多 5 路并行，加快「先摸清项目」
写/执行（写文件、删文件、跑命令）：一把锁串行，避免两个写同时改同一文件、或编译和写文件打架
4.规则 + LLM 意图路由
用户一句话先分类，再决定怎么处理。IntentService：
规则层（< 1ms）：关键词/模式能高置信（≥0.8）就直接定意图
LLM 层（100–500ms）：规则吃不准再让小模型分
5.任务拆解
「把项目部署到服务器并配 nginx」这种长请求，TaskBreakdownService 会拆成 2～10 个子任务（标题、描述、预期工具），
按会话缓存，ReAct 一轮一轮做。规则先识别「部署/重构/迁移」等复杂词，再让 LLM 出结构化清单。
